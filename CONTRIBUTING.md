# Contributing

Feedback about actual use is as valuable as code. Use the accessibility feedback
template to describe a task, where it became difficult, and what you would
prefer. Screen-reader and operating-system details are optional.

For a code change:

1. Keep it small and explain the problem and resulting behavior.
2. Run `python -m unittest -v` from the project root.
3. Add a meaningful behavior check for changed execution or navigation rules.
4. Retain plain-text explanations and explicit user control of audio.
5. Use synthetic data in tests and shared reports.

Please avoid claims of better AI accuracy or accessibility without matching
evidence. Actual participant feedback should be clearly separated from mock
player tests and authored control programs. Do not publish private material in
an issue or pull request. No personal diagnosis is needed for feedback.

contribution, you confirm that you can license that contribution on these terms.
